Phương pháp: biến một chương của RM0090 thành driver của riêng bạn

Thời lượng ~15 phút · Nguồn chính nên đọc sau: RM0090, chương 6 (GPIO)

Vì sao bài này quan trọng

Mission của bạn không phải là "có một driver GPIO chạy" — bạn đã có rồi. Mission là: đọc datasheet và tự viết driver cho bất kỳ ngoại vi (Timer, DMA, CAN...). Bài này dạy cái phương pháp: một quy trình 5 bước lặp lại được, dùng GPIO làm ví dụ vì bạn đã quen nó. Học được quy trình này, mỗi ngoại vi mới chỉ là thay thế tên register.

Bước 1 — Đọc danh sách register từ RM0090

Mỗi chương ngoại vi trong RM0090 có một bảng "register map" (VD chương 6, mục 6.4). Nó liệt kê từng register, địa chỉ offset, tên đầy đủ và mô tả. Với GPIO:

OffsetTênChức năng
0x00MODERChọn chế độ từng pin (in/out/AF/analog)
0x04OTYPEROutput type: push-pull / open-drain
0x08OSPEEDRTốc độ output
0x0CPUPDRPull-up / pull-down
0x10IDRInput data (đọc mức pin)
0x14ODROutput data (ghi mức pin)
0x18BSRRSet/reset từng bit (ghi atomic)
0x20AFRL/AFRHChọn chức năng thay thế AF0–AF15

Trong code của bạn, struct GPIO_TypeDef trong stm32f407xx.h chính là bảng này dưới dạng C — mỗi thành viên khớp một offset. Đó là lý do bạn viết pGPIOx->BSRR thay vì *(volatile uint32_t*)(GPIOA_BASE + 0x18): bản đồ register đã được "đóng gói" sẵn.

Bước 2 — Tìm vùng "chức năng" bạn cần

Đừng đọc cả chương. Mỗi lần viết hàm, chỉ tra đúng vùng bạn cần:

  • Cần bật clock cho GPIO → mục RCC trong RM0090 (bảng AHB1ENR), trong code của bạn là GPIO_PeriClockControl().
  • Cần cấu hình chân → phần mô tả MODER/PUPDR/OSPEEDR/OTYPER.
  • Cần set một chân → mô tả BSRR (set bit 0–15, reset bit 16–31).
Quy tắc đọc hiệu quả: tìm mục tiêu trước, đọc sau. Bảng offset (Bước 1) cho bạn biết register nào tồn tại; mô tả từng register cho bạn biết bit nào làm gì. Bạn không bao giờ cần đọc hết một chương.

Bước 3 — Chọn cấu trúc dữ liệu (phong cách OOP/HAL)

Theo phong cách bạn đang theo: tách thành config struct (mô tả "muốn cái gì") và handle struct (buộc config vào một ngoại vi cụ thể). Nhìn gpio_driver.h của bạn:

typedef struct {
    uint8_t GPIO_PinNumber;
    uint8_t GPIO_PinMode;
    uint8_t GPIO_PinSpeed;
    uint8_t GPIO_PinPuPdControl;
    uint8_t GPIO_PinOPType;
    uint8_t GPIO_PinAltFunMode;
} GPIO_PinConfig_t;         // config: MÔ TẢ

typedef struct {
    GPIO_TypeDef *pGPIOx;
    GPIO_PinConfig_t GPIO_PinConfig;
} GPIO_Handle_t;            // handle: config + ngoại vi cụ thể

Mẹo để nhớ: mỗi field của config struct tương ứng với một register. 6 field = 6 register (MODER, OTYPER, OSPEEDR, PUPDR, ...). Khi bạn thiết kế config struct cho một ngoại vi mới, hãy tự hỏi: field nào ánh xạ register nào? Nếu có field không ánh xạ register nào, thường là nó không cần thiết.

Bước 4 — Viết hàm Init: config → ghi register

Bước "dịch" config thành lệnh ghi. Logic chung cho mọi ngoại vi:

void GPIO_Init(GPIO_Handle_t *h) {
    // 1. clear vùng bit cần cấu hình
    // 2. shift config field vào vị trí đúng trong register
    // 3. ghi (|=) vào register
    h->pGPIOx->MODER   |= (h->GPIO_PinConfig.GPIO_PinMode << (pin*2));
    h->pGPIOx->OSPEEDR |= (h->GPIO_PinConfig.GPIO_PinSpeed << (pin*2));
    // ...OTYPER, PUPDR...
}

Hai phép dịch quen thuộc cần nhớ: mỗi chân chiếm 2 bit trong MODER/OSPEEDR/PUPDR (nên shift pin*2), và chỉ 1 bit trong OTYPER. Dịch sai số bit là bug kinh điển — vậy nên phải xác nhận từ RM0090 trước khi dịch.

Bước 5 — Viết hàm thao tác: đọc/ghi đúng register

Các hàm "điều khiển" gần như trực tiếp chạm register. Ví dụ trong driver của bạn:

void GPIO_Write_Pin(GPIO_Handle_t *h, uint8_t pin, uint8_t val) {
    if (val == 1) h->pGPIOx->BSRR |= (1 << pin);   // set: dùng BSRR
    else          h->pGPIOx->BSRR |= (1 << (pin + 16)); // reset: bit 16-31
}
uint8_t GPIO_Read_Pin(GPIO_Handle_t *h, uint8_t pin) {
    return (h->pGPIOx->IDR >> pin) & 1;            // đọc: dùng IDR
}

Lưu ý tinh tế: ghi output dùng BSRR chứ không phải ODR. Vì sao? Vì BSRR ghi atomic từng bit — không bị lỗi "read-modify-write race" khi đang đọc ODR thì bị ngắt. Đây chính là loại chi tiết bạn chỉ học được khi đọc chú thích trong RM0090, không phải khi copy-paste. (Bạn đã sửa bug này — xem ghi chú trong document/driver.)

Phương pháp 5 bước tóm tắt: (1) đọc bảng register map → (2) chỉ tra vùng chức năng cần → (3) thiết kế config/handle struct sao cho field ánh xạ register → (4) viết Init = dịch config thành ghi register → (5) viết hàm thao tác = đọc/ghi đúng register (nhớ BSRR vs ODR, IDR cho input).

Áp dụng cho ngoại vi tiếp theo

Khi bạn viết driver Timer hoặc DMA, hãy tự đi qua đúng 5 bước này và nói ra thành tiếng cho mình nghe từng bước. Đó là bài tập luyện. Nếu kẹt ở một register, chỉ mở đúng mô tả register đó trong RM0090.

Trắc nghiệm nhanh (bấm thử)

Để set chân PA5 lên mức cao, ghi vào register nào?
Trong MODER, mỗi chân chiếm bao nhiêu bit?
Đọc mức hiện tại của một chân (input) dùng register nào?

Để nhớ lâu

  • Nhớ lại: đóng trang này, tự viết lại 5 bước trên giấy. Nếu quên bước nào, lật lại — việc cố nhớ chính là lúc não bạn xây "storage strength".
  • Spacing: trước bài sau, hãy tự nhắc lại bản đồ register GPIO (8 register, offset & chức năng) mà không mở lại.
  • Primary source: đọc RM0090 chương 6 (GPIO) — bạn sẽ thấy mọi thứ ở trên nằm nguyên trong datasheet.
