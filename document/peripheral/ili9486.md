# ILI9486 LCD Driver (ngoại vi)

**Version: 1.1 — Ngày: 2026-07-27**

Changelog:
- 1.0 (2026-07-25) — Driver ban đầu (đặt tên sai là ILI9488), fix bug BSRR dùng raw pin index làm bitmask, fix MADCTL bị mirror chữ.
- 1.1 (2026-07-27) — Đổi tên đúng chip ILI9486, bỏ chân backlight (board không có BL), thêm layer `ILI9486_Ops_t` (function pointer cho setup-level: pin_set/pin_clear/delay_ms).

## Tổng quan

Driver cho LCD shield 3.5" 320x480, controller **ILI9486** (xem lại: [shield 3.5" Arduino/Uno/Mega2560](https://lkcg.vn/man-hinh-arduino-tft-shield-3-5-inch-320x480-uno-mega2560)), giao tiếp qua bus **8080 8-bit parallel** (không dùng SPI).

Nằm ở `Peripheral/inc/ili9486.h` và `Peripheral/src/ili9486.c`. Đây là driver **ngoại vi** (peripheral rời gắn ngoài board, khác với driver GPIO/SPI/RCC là driver nền tảng của chip) — nên áp dụng pattern function-pointer cho phần setup-level, không đụng tới các driver nền tảng.

Không dùng qua `gpio_driver.h` API — file này ghi trực tiếp thanh ghi `BSRR`/`ODR` của `GPIO_TypeDef` để đạt tốc độ tối đa khi fill màn hình.

## Giao diện 8080 8-bit parallel

| Tín hiệu | Ý nghĩa | Active |
|----------|---------|--------|
| CSX  | Chip select | Low |
| D/CX | Data/Command select (0 = command, 1 = data) | — |
| WRX  | Write strobe, latch dữ liệu ở sườn lên (rising edge) | Low |
| RDX  | Read strobe | Low |
| RESX | Hardware reset | Low |
| DB[7:0] | Data bus 8-bit, đặt trên 1 port liên tục | — |

Timing tối thiểu (datasheet trang 298): `tWRL/tWRH ≥ 15ns`, `tWC ≥ 66ns`, `tDST/tDHT ≥ 10ns`. Ở 168MHz, một lần ghi GPIO ≈ 12-18ns nên cần thêm `__NOP()` để đảm bảo pulse width.

### Pin mapping hiện tại (project)

| Chân MCU | Tín hiệu LCD |
|----------|--------------|
| PB0 | D/CX |
| PB1 | RESX |
| PB2 | CSX |
| PB5 | WRX |
| PB4 | RDX |
| PD0-PD7 | DB[7:0] |

Không có chân backlight — board này không có mạch điều khiển BL riêng.

## Struct và cấu hình

```c
typedef struct {
    void (*pin_set)(GPIO_TypeDef *port, uint16_t pin);
    void (*pin_clear)(GPIO_TypeDef *port, uint16_t pin);
    void (*delay_ms)(uint32_t ms);
} ILI9486_Ops_t;

typedef struct {
    GPIO_TypeDef *data_port;
    uint8_t       data_pin_offset;

    GPIO_TypeDef *cs_port;   uint16_t cs_pin;
    GPIO_TypeDef *dc_port;   uint16_t dc_pin;
    GPIO_TypeDef *wr_port;   uint16_t wr_pin;
    GPIO_TypeDef *rd_port;   uint16_t rd_pin;
    GPIO_TypeDef *rst_port;  uint16_t rst_pin;

    ILI9486_Ops_t ops;

    uint16_t width;
    uint16_t height;
} ILI9486_t;

extern ILI9486_t lcd;
```

Cấu hình trong `main.c`:
```c
lcd.data_port = GPIOD;  lcd.data_pin_offset = 0;
lcd.cs_port   = GPIOB;  lcd.cs_pin   = GPIO_PIN_NO_2;
lcd.dc_port   = GPIOB;  lcd.dc_pin   = GPIO_PIN_NO_0;
lcd.wr_port   = GPIOB;  lcd.wr_pin   = GPIO_PIN_NO_5;
lcd.rd_port   = GPIOB;  lcd.rd_pin   = GPIO_PIN_NO_4;
lcd.rst_port  = GPIOB;  lcd.rst_pin  = GPIO_PIN_NO_1;

ILI9486_Init();          /* tự gán ops mặc định nếu chưa gọi ILI9486_SetOps() */
ILI9486_SetRotation(1);  /* landscape */
```

### Setup-level ops (function pointer)

`ILI9486_Ops_t` chỉ áp dụng cho các hàm gọi **ít lần** (Reset, WriteCmd, WriteData, StartData, EndData — mỗi lệnh/burst gọi 1 lần). Hot path ghi pixel (`WR_STRB`, `SET_DATA`, hàng trăm nghìn lần/lần FillScreen) **giữ nguyên macro/inline trực tiếp BSRR**, không đi qua con trỏ hàm — vì indirect call qua con trỏ hàm thường không được compiler inline, sẽ làm chậm benchmark tốc độ RGB666/RGB565.

```c
void ILI9486_SetOps(const ILI9486_Ops_t *ops);
```
Gọi trước `ILI9486_Init()` nếu muốn thay bằng driver GPIO khác hoặc mock (ví dụ cho unit test không có hardware thật). Không gọi thì `ILI9486_Init()` tự dùng ops mặc định (ghi BSRR trực tiếp, giống hành vi cũ).

## Pixel format (3Ah) — RGB565 / RGB666

Chọn tại compile-time qua `#define ILI9486_PIXFMT` (mặc định `ILI9486_PIXFMT_RGB666`) trong `ili9486.h`.

| Format | Byte/pixel | Color type | Số màu |
|--------|-----------|------------|--------|
| RGB565 (0x55) | 2 | `uint16_t` | 65K |
| RGB666 (0x66) | 3 | `uint32_t` (0xRRGGBB) | 262K |

RGB666 tốn thêm 50% băng thông bus so với RGB565 (3 byte vs 2 byte mỗi pixel) — dùng `LCD_Test_FillSpeed()` trong `main.c` để đo trực tiếp trên hardware.

## API chính

```c
void ILI9486_Reset(void);
void ILI9486_Init(void);
void ILI9486_SetOps(const ILI9486_Ops_t *ops);

void ILI9486_EnterSleep(void);
void ILI9486_ExitSleep(void);

void ILI9486_FillScreen(ILI9486_Color_t color);
void ILI9486_FillRectangle(uint16_t x, uint16_t y, uint16_t w, uint16_t h, ILI9486_Color_t color);
void ILI9486_DrawPixel(uint16_t x, uint16_t y, ILI9486_Color_t color);
void ILI9486_DrawLine(uint16_t x0, uint16_t y0, uint16_t x1, uint16_t y1, ILI9486_Color_t color);

void ILI9486_DrawChar(uint16_t x, uint16_t y, char c, FontDef *font, ILI9486_Color_t color, ILI9486_Color_t bg);
void ILI9486_DrawString(uint16_t x, uint16_t y, char *str, FontDef *font, ILI9486_Color_t color, ILI9486_Color_t bg);
```

`ILI9486_DrawStringFast` build sẵn buffer pixel trong BSS rồi ghi 1 burst duy nhất (nhanh hơn `DrawString` vốn gọi `SetAddressWindow` cho từng ký tự).

## Common mistakes & debug tips

- **BSRR dùng raw pin index làm bitmask** — bug gốc gây RST/CS nhảy sai chân: `BSRR = pin << 16` chỉ đúng nếu `pin` đã là `(1u << pin_index)`, không phải index thô. Luôn dùng `(1u << lcd.xx_pin) << 16u`.
- **MADCTL thiếu MX/MY** — landscape (MV) mà thiếu MX hoặc MY sẽ làm chữ/ảnh bị mirror ngang. Hướng mirror phụ thuộc từng lô module, thử đổi MX ↔ MY nếu vẫn ngược.
- **ODR reset = 0 sau GPIO_Init()** — CS/WR/RD/RST đều LOW ngay sau khi cấu hình pin, cần set về trạng thái nghỉ (CS=1, WR=1, RD=1, RST=1) trước khi gọi `ILI9486_Init()`.
- **Comment pin mismatch** — luôn đối chiếu comment với `GPIO_PIN_NO_x` thực tế trong code khi đổi board/pin, dễ lệch khi refactor.
- **Không có chân backlight trên board này** — không gọi `Backlight_On/Off` (đã bỏ khỏi driver từ v1.1); nếu board khác có BL, tự thêm lại field + hàm tương ứng.
